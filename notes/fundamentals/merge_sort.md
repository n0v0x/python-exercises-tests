## 1. Алгоритм сортировки слиянием

**Алгоритм состоит из двух независимых частей:**
1. Разделение с рекурсией — превращает неотсортированный список в набор отсортированных кусков, а потом собирает их обратно.
2. Слияние — берёт два отсортированных списка и делает из них один отсортированный.

**Слияние** — самостоятельная операция. Её можно написать и проверить отдельно, до всякой рекурсии.

### Часть 1. Слияние двух отсортированных списков
**Вход:** два списка, каждый уже отсортирован по возрастанию. Назовём их `A` и `B`.

**Выход:** один список, содержащий все элементы `A` и `B`, отсортированный по возрастанию.

**Логика:**
1. Создать пустой список `R` — сюда будем складывать результат.
2. Поставить указатель `i` на начало `A` (индекс `0`). Поставить указатель `j` на начало `B` (индекс `0`).
3. Повторять, пока оба указателя не вышли за пределы своих списков:
    * Сравнить элемент `A[i]` и элемент `B[j]`.
    * Если `A[i]` меньше или равен `B[j]` — добавить `A[i]` в конец `R`, сдвинуть `i` на один вперёд.
    * Иначе — добавить `B[j]` в конец `R`, сдвинуть `j` на один вперёд.
4. Когда цикл закончился — один из списков исчерпан, другой может иметь остаток. Остаток уже отсортирован (он был отсортирован с самого начала), поэтому его не надо сравнивать — просто добавить в конец `R` все элементы, начиная с текущей позиции указателя, до конца списка.
5. Вернуть `R`.

**Ключевые свойства, которые делают это возможным:**
* Оба входа отсортированы. Поэтому элемент на указателе — наименьший из ещё не взятых в своём списке. Сравнивая два таких «наименьших», мы всегда берём наименьший из всех оставшихся. Это и есть инвариант.
* Указатели двигаются только вперёд. Поэтому слияние — один проход, O(n).
* Остаток доклеивается с текущей позиции указателя, а не со следующей. Указатель уже стоит на первом необработанном элементе.

### Часть 2. Сортировка списка рекурсией
**Вход:** список arr.

**Выход:** новый список, содержащий те же элементы, отсортированные по возрастанию.

**Логика:**
1. База. Если длина `arr` равна `0` или `1` — вернуть `arr` как есть. Один элемент (или ноль) уже отсортирован. Это единственное место, где рекурсия останавливается.
2. Разделение. Вычислить середину: целая часть от деления длины на `2`. Назовём её `mid`.
3. Левая половина. Взять срез `arr` от начала до `mid` не включая. Это левая часть.
4. Правая половина. Взять срез `arr` от `mid` включая до конца. Это правая часть.
5. Отсортировать левую. Вызвать эту же функцию для левой половины. Дождаться результата. Сохранить его.
6. Отсортировать правую. Вызвать эту же функцию для правой половины. Дождаться результата. Сохранить его.
7. Слить. Вызвать операцию слияния (часть 1) для двух полученных отсортированных половин. Вернуть её результат.

**Ключевые свойства:**
* Срезы на шагах 3–4 не пересекаются и покрывают весь исходный список. Каждый элемент попадает ровно в одну половину.
* Левая часть не включает `mid`, правая включает — иначе элемент попадёт в обе или потеряется.
* Сначала рекурсия полностью уходит вглубь по левой ветке, доходит до базы, возвращается, сливает, потом идёт в правую. Это depth-first.
* Каждый рекурсивный вызов получает список строго короче родительского (потому что `mid` меньше длины при длине ≥ 2). Поэтому рекурсия конечна.
* На обратном пути каждый уровень сливает две отсортированные половины в одну. К моменту возврата из самого верхнего вызова весь список отсортирован.

**Что важно не перепутать при реализации:**
1. База — `<= 1`, а не `< 1` или `== 0`. Пустой список и список из одного элемента оба уже отсортированы.
2. mid — целочисленное деление. Иначе срез не сработает.
3. Левая часть — до `mid` не включая, правая — с `mid` включая. Проверь на нечётной длине: `[1,2,3]`, `mid = 1`, левая `[1]`, правая `[2,3]`. Элемент `3` — в правой, не потерян.
4. Условие цикла слияния — `И`, не `ИЛИ`. Крутимся, пока оба указателя в пределах. Как только один вышел — цикл закончился.
5. Остаток доклеивается с текущей позиции указателя. Если `i` указывает на первый необработанный элемент `A`, то остаток — `A` начиная с `i`. Не с `i+1`.
6. При равенстве в слиянии — бери из левой.Это сохраняет устойчивость (равные элементы не меняют относительный порядок). На результат сортировки не влияет, но на устойчивость — да.
7. Не сортируй повторно то, что уже отсортировано. `left` и `right` уже отсортированы после рекурсивных вызовов. Слияние — единственное, что нужно сделать с ними. Не надо их ещё раз сортировать или проверять.
8. Возвращай новый список, а не мутируй исходный. На каждом уровне создаются новые списки. Исходный arr не меняется.

## 2. Пример трассировки рекурсией 

Пример списка: [5, 3, 1, 6, 2, 7]

**Условные обозначения:**
* Отступ слева = глубина стека.
* Стрелки ↓ — идём в рекурсию (вниз).
* Стрелки ↑ — возвращаемся (вверх).
* ▶ — что делает функция на этом уровне.

### Фаза 1: спуск по левой ветке
```
merge_sort([5, 3, 1, 6, 2, 7])                      ← вызов 1, стек: [1]
  mid = 3
  left  = merge_sort([5, 3, 1])  ↓                  ← вызов 2, стек: [1, 2]

    merge_sort([5, 3, 1])
      mid = 1
      left  = merge_sort([5])  ↓                     ← вызов 3, стек: [1, 2, 3]

        merge_sort([5])
          len = 1 → база, возвращаем [5]  ↑          ← вызов 3 завершён

      left = [5]                                     ← вызов 2 продолжается
      right = merge_sort([3, 1])  ↓                  ← вызов 4, стек: [1, 2, 4]

        merge_sort([3, 1])
          mid = 1
          left  = merge_sort([3])  ↓                 ← вызов 5, стек: [1, 2, 4, 5]

            merge_sort([3])
              len = 1 → база, возвращаем [3]  ↑      ← вызов 5 завершён

          left = [3]                                 ← вызов 4 продолжается
          right = merge_sort([1])  ↓                 ← вызов 6, стек: [1, 2, 4, 6]

            merge_sort([1])
              len = 1 → база, возвращаем [1]  ↑      ← вызов 6 завершён

          right = [1]
          ▶ merge([3], [1]) = [1, 3]
          возвращаем [1, 3]  ↑                       ← вызов 4 завершён

      right = [1, 3]
      ▶ merge([5], [1, 3]) = [1, 3, 5]
      возвращаем [1, 3, 5]  ↑                        ← вызов 2 завершён

  left = [1, 3, 5]                                   ← вызов 1 продолжается
  right = merge_sort([6, 2, 7])  ↓                   ← вызов 7, стек: [1, 7]
```
**Ключевое:** пока не дошли до базы в самом левом углу ([5]), ни одного merge не было. Всё, что происходило, — это деление и спуск. merge начинается только на обратном пути, когда стек начал разворачиваться.

### Фаза 2: спуск по правой ветке
```
    merge_sort([6, 2, 7])                            ← вызов 7, стек: [1, 7]
      mid = 1
      left  = merge_sort([6])  ↓                     ← вызов 8, стек: [1, 7, 8]

        merge_sort([6])
          len = 1 → база, возвращаем [6]  ↑          ← вызов 8 завершён

      left = [6]
      right = merge_sort([2, 7])  ↓                  ← вызов 9, стек: [1, 7, 9]

        merge_sort([2, 7])
          mid = 1
          left  = merge_sort([2])  ↓                 ← вызов 10, стек: [1, 7, 9, 10]

            merge_sort([2])
              len = 1 → база, возвращаем [2]  ↑      ← вызов 10 завершён

          left = [2]
          right = merge_sort([7])  ↓                 ← вызов 11, стек: [1, 7, 9, 11]

            merge_sort([7])
              len = 1 → база, возвращаем [7]  ↑      ← вызов 11 завершён

          right = [7]
          ▶ merge([2], [7]) = [2, 7]
          возвращаем [2, 7]  ↑                       ← вызов 9 завершён

      right = [2, 7]
      ▶ merge([6], [2, 7]) = [2, 6, 7]
      возвращаем [2, 6, 7]  ↑                        ← вызов 7 завершён

  right = [2, 6, 7]                                  ← вызов 1 продолжается
```

### Фаза 3: верхний merge и возврат
```
merge_sort([5, 3, 1, 6, 2, 7])                       ← вызов 1, стек: [1]
  left  = [1, 3, 5]
  right = [2, 6, 7]
  ▶ merge([1, 3, 5], [2, 6, 7]) = [1, 2, 3, 5, 6, 7]
  возвращаем [1, 2, 3, 5, 6, 7]  ↑                   ← стек пуст, всё готово
```

## 3. Технические заметки по реализации

### 3.1 List comprehension

**List comprehension** — это  это про создание списка/словаря/множества одной строкой, когда вместо цикла с append пишется выражение в квадратных скобках.

**List comprehension**  используется в функции `strings_to_ints`.

```
# было — цикл с append
result = []
for item in input_str:
    result.append(int(item))

# стало — list comprehension
result = [int(item) for item in input_str]
```
Вот это `[int(item) for item in input_str]` — **list comprehension**. Читается как «_список int(item) для каждого item из input_str_».

### 3.2 Inline variables

Прием **Inline variable** (inline-замена переменной) - «убрать промежуточную переменную» или «свернуть в одно выражение».
Inline variables используется в функциях `parse_from_input` и `parse_from_argv`.
```
# было
input_list = strings_to_ints(input_str_stdin)
return input_list

# стало — inline
return strings_to_ints(input_str_stdin)
```

Переменная `input_list` жила одну строку — её присваивали и сразу возвращали. Значит, она не нужна: можно подставить выражение прямо в `return`, а переменную убрать.

**Уместно, если переменная:**
* используется ровно один раз;
* сразу после присваивания возвращается;
* её имя не добавляет смысла (не объясняет, что это за значение);

В примере случай — ровно такой: `input_list` — это просто «результат вызова», имя ничего не проясняет.


**НЕ уместно, если:**
* переменная используется несколько раз:
```
result = strings_to_ints(input_str)
print(result)
return result

# result нужен дважды — inline невозможен без дублирования вызова.
```
* имя переменной объясняет её смысл:
```
normalized_emails = [e.lower().strip() for e in raw_emails]
return normalized_emails

# normalized_emails говорит читателю, что вернулось. 
# return [e.lower().strip() for e in raw_emails] — читается хуже, потому что смысл «нормализованные email» потерялся.
```
* выражение длинное или сложное:
```
total = sum(item.price * item.quantity for item in cart if item.available)
return total

# В одну строку return sum(...) — можно, но если выражение занимает 120 символов, промежуточная переменная разбивает его на две читаемые части.
```
* переменная нужна для отладки:
```
input_list = strings_to_ints(input_str)
print(input_list)      # ← временный принт для отладки
return input_list

# Пока отлаживаешь — переменная нужна. Уберёшь, когда закончишь.
```

### Как решить нужен такой рефакторинг или нет:

**Правило простое:** если переменная используется один раз и её имя не объясняет ничего нового — инлайни. 

Если имя добавляет смысл или переменная нужна ещё раз — оставь.

Для `input_list = strings_to_ints(...)`; `return input_list` — имя `input_list` не добавляет смысла (что ещё может вернуть `strings_to_ints`, кроме списка интеджеров?). Поэтому inline — правильный выбор.

### 3.3 Срез списка

**Срез** — это операция, которая берёт подсписок из списка: копию части элементов, без изменения исходного списка.

**Базовый синтаксис:**
```
arr[start:stop:step]
```
**Срез** записывается в квадратных скобках через двоеточие и читается: «_элементы списка `arr` с индекса `start` включая и до индекса `stop` не включая с шагом `step`_».

**Три параметра, все необязательные:**

| Параметр | Что означает                     |По умолчанию    |
|--------|----------------------------------|----------------|
| start  | с какого индекса начать (включая)|0 — начало      |
| stop   | до какого индекса (не включая)   |`len(arr)` — конец |
| step   | шаг между элементами             | 1 — каждый подряд |

### Срез создаёт новый список.

**Срез** не возвращает «вид» на исходный список (в отличие от NumPy). 
Он копирует элементы в новый список.

`arr[::-1]` — идиома «развернуть список». 

```
arr = [1, 2, 3, 4, 5]
sub = arr[1:3]        # sub = [2, 3] — новый список
sub[0] = 999          # меняем sub
print(arr)            # [1, 2, 3, 4, 5] — arr не изменился
print(sub)            # [999, 3]
```

### Примеры срезов:
arr = [10, 20, 30, 40, 50]

arr[1:3]     # [20, 30]      — с 1 по 2 включительно (3 не входит)

arr[:3]      # [10, 20, 30]  — с начала до 2 включительно

arr[2:]      # [30, 40, 50]  — с 2 до конца

arr[:]       # [10, 20, 30, 40, 50]  — копия всего списка
arr[::2]     # [10, 30, 50]  — каждый второй
arr[1::2]    # [20, 40]      — каждый второй, начиная с 1
arr[1:4:2]   # [20, 40]      — с 1 до 3, шаг 2

Отрицательные индексы

Python поддерживает отрицательные индексы — считаются с конца:
Индекс	Элемент
0 или -5	10
1 или -4	20
2 или -3	30
3 или -2	40
4 или -1	50
python

arr[-2:]     # [40, 50]     — последние два
arr[:-2]     # [10, 20, 30] — всё, кроме последних двух
arr[-3:-1]   # [30, 40]     — с -3 до -2 включительно

Отрицательный шаг — разворот

Если step < 0, срез идёт справа налево. Тогда start должен быть больше stop, иначе получится пустой список.
python

arr[::-1]      # [50, 40, 30, 20, 10]  — весь список задом наперёд
arr[3:0:-1]    # [40, 30, 20]          — с 3 до 1 включительно, назад
arr[4:1:-2]    # [50, 30]              — с 4 до 2, шаг -2



Срез в левой части присваивания

Срез можно использовать не только для чтения, но и для записи:
python

arr = [1, 2, 3, 4, 5]
arr[1:3] = [20, 30, 40]     # заменить элементы 1..2 на три новых
print(arr)                  # [1, 20, 30, 40, 4, 5]

Длина может меняться — список растянется или сожмётся:
python

arr = [1, 2, 3, 4, 5]
arr[1:4] = [99]             # заменить три элемента одним
print(arr)                  # [1, 99, 5]

arr[1:1] = [7, 8]           # вставить в позицию 1 (пустой срез)
print(arr)                  # [1, 7, 8, 99, 5]

arr[1:3] = []               # удалить элементы 1..2
print(arr)                  # [1, 99, 5]

Как срезы используются в merge sort

В merge sort срезы — основной инструмент деления:
python

mid = len(arr) // 2
left  = arr[:mid]      # с начала до mid, НЕ включая mid
right = arr[mid:]      # с mid до конца, ВКЛЮЧАЯ mid

    arr[:mid] — левая половина, элементы с индексами 0..mid-1.

    arr[mid:] — правая половина, элементы с индексами mid..len-1.

Вместе они покрывают весь список: mid попадает только в правую, левая — до mid не включая. Без пересечений, без потерь.

Граничные случаи

Пустой срез — когда start >= stop при положительном шаге (или start <= stop при отрицательном):
python

arr[3:1]     # []  — start > stop, пусто
arr[10:20]   # []  — за пределами, пусто (не ошибка!)
arr[0:0]     # []  — пусто

Индексы за пределами — Python не падает, а «обрезает» до реальных границ:
python

arr[2:100]   # [30, 40, 50]  — stop обрезан до len
arr[-100:2]  # [10, 20]      — start обрезан до 0
arr[100:]    # []            — start за пределами, пусто

Это отличается от arr[100] (без среза), который падает с IndexError. Срез мягче: «дай что есть в этих границах, если ничего — пусто».

Срез vs индекс
	arr[i]	arr[a:b]
Что возвращает	один элемент	список элементов
Тип результата	тип элемента (int)	list
Выход за границы	IndexError	обрезается или []
Можно ли присвоить	да	да (заменяет кусок)
python

arr = [10, 20, 30]
arr[1]      # 20      — int
arr[1:2]    # [20]    — list с одним элементом
arr[1:1]    # []      — list пустой

arr[1] и arr[1:2] дают разное: число и список. Не путай.

Частые ошибки

1. Забыть, что stop не включается.
python

arr[0:3]   # [10, 20, 30] — три элемента, не четыре
arr[0:4]   # [10, 20, 30, 40] — четыре

Если хочешь включить stop — пиши stop + 1: arr[0:3+1].

2. Думать, что срез — это view.

В Python срез копирует. Изменение среза не меняет исходный список (если не присваивать срез обратно). В NumPy, кстати, наоборот — срез даёт view. Не путай Python list и NumPy array.

3. arr[len(arr)] падает, а arr[len(arr):] — нет.

arr[5] на списке длины 5 → IndexError. arr[5:] → []. Срез терпимее.

4. arr[::0] — ошибка.

step = 0 запрещён: ValueError: slice step cannot be zero. Логично: «шаг ноль» не имеет смысла.

5. Путать arr[:] и arr.

arr[:] — копия. arr — тот же объект. Если передать arr в функцию и изменить — изменится исходный. Если передать arr[:] — функция изменит копию, исходный не тронется.
Итог

    Срез — arr[start:stop:step], берёт подсписок.

    start включается, stop не включается.

    Все параметры необязательны; по умолчанию 0, len, 1.

    Отрицательные индексы — с конца; отрицательный шаг — разворот.
